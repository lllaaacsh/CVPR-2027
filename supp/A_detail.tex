\subsection{Architecture and training formulation}
\label{app:supp_formulation}

\paragraph{Router architecture and gradient saliency.}
    \ji{
    On mimic-video~\cite{pai2025mimicvideo}, the router takes the future tokens after video block 2 (2048-d) and the instruction tokens that condition the video backbone (1024-d T5 embeddings).
    A linear layer projects each future token to 1024 dimensions, followed by rotary positional encoding.
    A single 8-head cross-attention layer allows every future token to attend to the instruction tokens with padding masked.
    The cross-attention output is added residually to the projected token, and a two-layer MLP (1024 $\to$ 128 $\to$ 1 with GELU activation) followed by a sigmoid outputs $s_{t,p} \in [0, 1]$.
    In total, the router contains 6.4M parameters (2.1M linear projection, 4.2M cross-attention, and 0.13M MLP), compared with 2B parameters in the frozen video DiT.
    Analytically (counting two operations per multiply-accumulate), scoring all 16,800 future tokens requires approximately 0.18 TFLOPs, corresponding to 0.2\% of a full-context query (98.0 TFLOPs) and 0.4\% of a 20\%-budget query (42.7 TFLOPs).
    On DiT4DiT~\cite{ma2026dit4dit}, the router follows the same architecture after video block \suppdraft{2}.
    }

\suppdraft{For both DiT4DiT configurations (LIBERO and RoboCasa-GR1), the future-token and instruction inputs are 2,048- and 1,024-dimensional, respectively.
The router uses 1,024-dimensional cross-attention with eight heads and an MLP with widths 1,024--128--1, for 6,427,905 trainable parameters.
The input dimensions, parameter count and insertion point after the second video transformer block are shared by both configurations.}



    \ji{
    Selecting the top-$F$ spatial groups at full resolution is a discrete operation whose piecewise-constant ranking yields zero gradient with respect to $S_g$.
    To enable gradient supervision without altering forward activations, every tube constructed from group $g$ (four tubes if kept at full resolution, or one merged tube otherwise) is scaled by a multiplicative straight-through estimator (STE)~\cite{bengio2013estimating}:
    \begin{equation}
        \gamma_g = 1 + S_g - \operatorname{sg}(S_g),
        \label{eq:supp_ste}
    \end{equation}
    where $\operatorname{sg}(\cdot)$ denotes the stop-gradient operator.
    In the forward pass, $\gamma_g = 1$, ensuring identical computation between training and deployment; in the backward pass, $\partial \gamma_g / \partial S_g = 1$.
    Writing $\tilde{z}_i = \gamma_{g(i)} z_i$ for each token $i$ belonging to group $g(i)$, the chain rule yields
    \begin{equation}
        \frac{\partial \mathcal{L}_{\text{task}}}{\partial S_g} = \sum_{i : g(i) = g} \left\langle \frac{\partial \mathcal{L}_{\text{task}}}{\partial \tilde{z}_i},\, z_i \right\rangle,
        \label{eq:supp_chain}
    \end{equation}
    which measures the first-order sensitivity of the task loss to scaling up group $g$'s representation.
    Equation~(3) of the main paper retains the non-negative descent component, $r_g = \max(0, -\partial \mathcal{L}_{\text{task}} / \partial S_g)$, assigning a high saliency when emphasizing group $g$ reduces $\mathcal{L}_{\text{task}}$.
    Through \cref{eq:supp_ste}, the router receives both direct task gradients $\partial \mathcal{L}_{\text{task}} / \partial S_g$ and stabilized pseudo-label supervision described below, without requiring a full-context probe at test time.
    }


\paragraph{Router objective and target smoothing.}
    \ji{
    For each sample $i$ at training step $n$, we compute the per-sample gradient saliency:
    \begin{equation}
        r_g^{(i,n)} = \max\!\left(0,\, -\frac{\partial \mathcal{L}_{\text{task}}^{(i)}}{\partial S_g^{(i)}}\right).
        \label{eq:supp_saliency}
    \end{equation}
    To reduce gradient variance across stochastic flow-matching steps, we track an exponential moving average (EMA) of the batch-mean saliency $\bar{r}_g^{(n)}$ with momentum $\mu = 0.9$:
    \begin{equation}
        m_g^{(n)} = \mu m_g^{(n-1)} + (1 - \mu)\bar{r}_g^{(n)}.
        \label{eq:supp_ema}
    \end{equation}
    Each sample's smoothed saliency blends this running group statistic with its instantaneous sample gradient:
    \begin{equation}
        \tilde{r}_g^{(i,n)} = \mu m_g^{(n)} + (1 - \mu) r_g^{(i,n)},
        \label{eq:supp_smooth}
    \end{equation}
    from which we construct per-sample binary pseudo-labels by marking the top-$F$ groups:
    \begin{equation}
        y_g^{(i)} = \mathbb{I}\!\big[g \in \operatorname{Top-}F\big(\tilde{r}^{(i,n)}\big)\big].
        \label{eq:supp_pseudolabel}
    \end{equation}
    If a sample yields zero positive saliency across all groups, we substitute its detached current scores $S_g^{(i)}$ prior to \cref{eq:supp_smooth} to avoid degenerate all-zero targets.
    Both the EMA statistics and pseudo-labels are used strictly during training; at inference, the router predicts $s_{t,p}$ directly from shallow video features and instruction embeddings.
    }

    \ji{
    Let $q_g = S_g$ when $y_g = 1$ and $q_g = 1 - S_g$ when $y_g = 0$, and let $\rho = F / G$ denote the target fraction of full-resolution groups.
    The router loss terms in Eq.~(4) of the main paper are defined as
    \begin{align}
        \mathcal{L}_{\text{focal}} &= -\frac{1}{G} \sum_{g=1}^{G} \alpha_{y_g} (1 - q_g)^{\gamma} \log q_g, \label{eq:supp_focal} \\
        \mathcal{L}_{\text{budget}} &= \left| \frac{1}{G} \sum_{g=1}^{G} S_g - \rho \right|, \label{eq:supp_budget} \\
        \mathcal{L}_{\text{entropy}} &= -\frac{1}{G} \sum_{g=1}^{G} \big[ S_g \log S_g + (1 - S_g) \log(1 - S_g) \big], \label{eq:supp_entropy}
    \end{align}
    averaged over the mini-batch with $\gamma = 2$ and $\lambda_b = \lambda_e = 0.1$.
    Class-balance weights follow effective-number weighting $\hat{\alpha}_c = (1 - \beta)/(1 - \beta^{n_c})$ with $\beta = 0.999$, normalized so that $\alpha_0 + \alpha_1 = 1$, where $n_c$ counts pseudo-labels of class $c \in \{0, 1\}$ in the batch.
    Scores are clipped to $[10^{-6}, 1 - 10^{-6}]$ inside logarithms for numerical stability.
    }
    




\paragraph{Temporal boundary placement and positional indexing.}

Let $h_{t,p}$ be the router's projected (pre-rotary) feature of tube $p$ in future frame $t$, computed after spatial merging.
The frame-to-frame variation is $\delta_{p,t}=1-\cos(h_{t,p},h_{t+1,p})$ and $\Delta_p=\frac{1}{T-1}\sum_t\delta_{p,t}$ enters the priority of \mainref{eq:priority}.
Tubes are sorted by $u_p$ and the tiers of \suppdraft{\cref{tab:supp_schedules}} are filled from the top, so the token budget is met exactly.
Within a tube with $K_p$ segments, let $c_t=\sum_{\tau<t}\delta_{p,\tau}$ be the cumulative variation, and place a candidate cut between frames $t$ and $t{+}1$ at $\bar c_t=(c_t+c_{t+1})/(2c_T)$.
The $K_p-1$ cuts $b_1<\dots<b_{K_p-1}$ minimize
\begin{equation}
  \sum_{q=1}^{K_p-1} \Big(\bar c_{b_q} - \frac{q}{K_p}\Big)^2 ,
  \label{eq:supp_cuts}
\end{equation}
so every segment covers about $1/K_p$ of the tube's total variation.
The ordered minimization is solved exactly by dynamic programming, with a $10^{-6}$-weighted term favouring equal-length cuts when variation costs are nearly tied; a tube without variation receives equal-length segments.
Each segment is replaced by the mean of its frames.

The video DiT uses 3D rotary embeddings factorized over time, height and width.
Spatially, every tube keeps the grid position of its top-left source position, so future tubes stay aligned with the observation tokens.
Temporally, contiguous-t gives the $k$-th segment of every tube the $k$-th future time index, regardless of the frames it covers.
Source-t instead gives a segment the index of its source frame closest to the segment's midpoint in cumulative variation; a tube with few segments then has large gaps between its indices, and tubes with different $K_p$ use different spacings (\mainref{fig:temporal_positions}).

\paragraph{Velocity distillation and adapter merging.}

For every training sample, the full-context teacher and the compressed student see the same inputs except for the allocation.
One video noise draw $\epsilon_v$ is shared by both contexts, with the future latents at the deployment noise level $\sigma=80$, so the two contexts differ only by compression.
The action decoder is a flow-matching model~\suppdraft{\cite{lipman2023flow}}: with a demonstrated action chunk $a$, a flow time $\tau$ drawn per sample from the released trainer's Beta distribution, and one action noise $\epsilon_a\sim\mathcal{N}(0,I)$,
\begin{equation}
  x_\tau=(1-\tau)\,a+\tau\,\epsilon_a, \qquad v_{\text{gt}}=\epsilon_a-a .
\end{equation}
The teacher $v_{\text{full}}$ is the original decoder (adapter disabled) on the full context and the student $v$ is the adapted decoder on the compressed context, both evaluated at the same $(x_\tau,\tau)$ and robot state, so
\begin{equation}
  \mathcal{L}_{\text{task}} = \norm{v - v_{\text{full}}}^2 + \lambda_{\text{GT}}\norm{v - v_{\text{gt}}}^2 ,
  \quad \lambda_{\text{GT}}=0.02 ,
  \label{eq:supp_task}
\end{equation}
as in \mainref{eq:task_loss}; no gradient flows into the teacher.
Sharing $\epsilon_v$, $\epsilon_a$ and $\tau$ prevents independent noise draws from confounding the comparison between full and compressed contexts.

At deployment each \suppdraft{LoRA-adapted} projection~\suppdraft{\cite{hu2022lora}} $W$ is replaced by $W+\frac{\alpha}{r}BA$ ($r=16$, $\alpha=8$), and the low-rank branch is removed; the folded decoder has the FLOPs of the original.

  \caption{Training \method\ on mimic-video (one suite).}
  \label{alg:supp_train}
  \footnotesize
  \begin{algorithmic}[1]
    \Require Frozen video DiT $V$ and decoder $D$;
    demonstrations; training and deployment
    budget schedules (\suppdraft{\cref{tab:supp_schedules}})

    \State Initialize router $R_\theta$,
    temporary decoder LoRA $\phi$, and saliency
    EMA state $m_g$

    \For{each Stage-1 training step}
      \Comment{Joint adaptation}

      \State Sample a batch of instructions,
      observations, actions $a$, and robot states;
      draw $\epsilon_v,\tau,\epsilon_a$

      \State $Z \gets
      V_{1:2}(\text{observation},\sigma\epsilon_v)$

      \State $s \gets
      R_\theta(Z_{\mathrm{fut}},\text{instruction})$;
      compute $S_g$ by
      \mainref{eq:group_score}

      \State Apply the Stage-1 spatial and temporal
      allocation; gate tubes by $\gamma_g$
      (\suppdraft{\cref{eq:supp_ste}})

      \State $C \gets V_{3:20}(\text{allocated }Z)$

      \State $C_{\mathrm{full}}
      \gets V_{3:20}(Z)$ without gradient

      \State $v \gets
      D_\phi(x_\tau,\tau,\text{state},C)$

      \State $v_{\mathrm{full}}\gets
      D(x_\tau,\tau,\text{state},C_{\mathrm{full}})$

      \State Compute per-sample
      $\mathcal{L}_{\mathrm{task}}^{(i)}$
      by \suppdraft{\cref{eq:supp_task}}

      \State $r_g^{(i)} \gets
      \max(0,
      -\partial\mathcal{L}_{\mathrm{task}}^{(i)}
      /\partial S_g^{(i)})$

      \State $\bar r_g \gets
      \operatorname{mean}_i r_g^{(i)}$

      \State $m_g \gets
      \mu m_g+(1-\mu)\bar r_g$
      \Comment{EMA update}

      \State $\tilde r_g^{(i)}
      \gets \mu m_g+(1-\mu)r_g^{(i)}$

      \State $y_g^{(i)}
      \gets \mathbb{I}
      [g\in\operatorname{TopF}(\tilde r^{(i)})]$

      \State Detach pseudo-labels;
      compute $\mathcal{L}_{\mathrm{router}}$
      by \mainref{eq:router_loss}

      \State Update $\theta,\phi$ using
      $\nabla(\mathcal{L}_{\mathrm{task}}
      +\mathcal{L}_{\mathrm{router}})$

    \EndFor

    \State Freeze the learned router $R_\theta$

    \For{each target token budget $b$}
      \Comment{Stage 2}

      \State Initialize a fresh rank-16
      decoder LoRA $\phi_b$

      \For{each Stage-2 training step}

        \State Sample demonstrations and
        flow-matching noise

        \State Compute early features $Z$
        and input-conditioned router scores

        \State Allocate future tokens using
        the deployed schedule for budget $b$

        \State Compute compressed context
        $C_b$ and full-context teacher
        features $C_{\mathrm{full}}$

        \State Compute student velocity
        $v_b$ and teacher velocity
        $v_{\mathrm{full}}$

        \State Compute $\mathcal{L}_{\mathrm{task}}$
        by \suppdraft{\cref{eq:supp_task}}

        \State Update only $\phi_b$
        using $\nabla_{\phi_b}
        \mathcal{L}_{\mathrm{task}}$

      \EndFor
    \EndFor

    \State \Return $R_\theta$ and
    budget-specific adapters $\{\phi_b\}$

  \end{algorithmic}
\end{algorithm}

\subsection{Benchmarks and evaluation protocols}
\label{app:supp_benchmarks}

\paragraph{LIBERO.}

Each of LIBERO-Spatial, -Object and -Goal~\suppdraft{\cite{liu2023libero}} has ten tasks; we evaluate 50 initial states per task, 500 episodes per suite, with the benchmark's initial states and episode limits.
Every method is evaluated on the same task-specific initial states within each evaluation seed, enabling paired comparisons. For each seed, we evaluate 50 episodes per task across 10 tasks, yielding 500 episodes per suite. We use three evaluation seeds, resulting in 1,500 evaluation episodes per method per suite. The reported success rates are averaged over the three seeds.

mimic-video~\suppdraft{\cite{pai2025mimicvideo}} uses the released suite-specific checkpoints and conditions on five RGB frames (two latent observation frames) and the robot state. The video model runs a single step at the deployment noise level, and five actions of each predicted chunk are executed before replanning.

LIBERO-Long is excluded because our reproduction lacks a corresponding checkpoint and evaluation configuration.
LIBERO recordings use MuJoCo 3.3.4; SIMPLER-Bridge uses its SAPIEN-based simulator, and RoboCasa-GR1 uses the released RoboCasa-GR1 environment.
Main-table runs used H100 GPUs. Additional ablations use A100 or H100 GPUs as identified in \suppdraft{\cref{tab:supp_depth,tab:supp_objectives,tab:supp_split,tab:supp_temporal}}; paired ablation tests use references from the same GPU campaign.

\paragraph{SIMPLER-Bridge.}

We use the four WidowX tasks of SIMPLER-Bridge~\suppdraft{\cite{li2024simpler}}: put the carrot on the plate, put the spoon on the towel, stack the green block on the yellow block, and put the eggplant in the basket, with 24 fixed episodes per task and evaluation seed (96 per seed). The reported protocol uses three evaluation seeds.
The released Bridge video model and action decoder are frozen; the observation and execution horizons match LIBERO (five frames, five executed actions).
Bridge has its own router, trained on 1,024 BridgeDataV2~\suppdraft{\cite{walke2023bridgedata}} episodes (50 held out) with $F=200$, uniform pooling into 12, 10 or 8 segments during joint training.

\paragraph{RoboCasa-GR1.}
RoboCasa-GR1~\suppdraft{\cite{nasiriany2024robocasa}} has 24 tabletop tasks for the GR1 humanoid: six place an object into an articulated container and close it, and 18 move a novel object between two receptacles (\suppdraft{\cref{tab:supp_pertask_gr1}}).
We evaluate 50 episodes per task and seed (1,200 per seed), with three evaluation seeds in the reported protocol. Pairing is by (seed, task, episode) when seed-level records are available.
DiT4DiT~\suppdraft{\cite{ma2026dit4dit}} uses the released GR1 checkpoint with a single $224{\times}224$ egocentric view and the robot state; its video model sees one observed and two future latent frames of $14{\times}14$ tokens (588 tokens), and part of the view is letterbox padding.

\paragraph{Real-robot kitchen tasks.}

The robot is a 7-DoF Franka Emika Panda with a Robotiq 2F-85 gripper in a toy kitchen, observed by one side-view RGB camera whose $1280{\times}720$ frames are resized to $480{\times}640$.
The observation and target-action streams use a 5\,Hz cadence: a query reads frames at $t-0.8,\dots,t$\,s and the end-effector state, predicts 15 end-effector targets at 0.2\,s spacing, executes the first five and replans.
Predicted actions are pose increments in the current end-effector frame, tracked by a Cartesian impedance controller.
All methods share the frozen Bridge video model and use task-specific action decoders fine-tuned on demonstrations of each task.
\suppdraft{\Cref{tab:supp_robot_tasks}} lists task descriptions and reported success criteria; every method is run for 15 trials per task.
\method retains 30\% of the future tokens (7,440 tokens in total).
The real-robot policies in \mainref{tab:real_robot} start from the task-specific 5,000-step \suppdraft{full-context} decoder checkpoints.
Router and adapter training use the corresponding demonstration splits, normalization statistics and instruction embeddings.
The two adaptation stages comprise 1,500 steps of joint router/temporary-LoRA training followed by 1,500 steps for a fresh budget-specific LoRA with the router frozen.
The two adaptation stages use AdamW, batch size one with eight accumulated samples, router/adapter learning rates $10^{-4}$/$4\times10^{-5}$, 100 warm-up steps and cosine decay to 5\%.
LoRA has rank 16 and $\alpha=8$; the deployment allocation retains $F=100$ groups with $K=(5,8,10)$ and counts $(120,180,300)$, giving 5,040 future and 7,440 total tokens.

\subsection{Allocation schedules and hyperparameters}
\label{app:supp_schedules}

\paragraph{Token budgets and tier schedules.}
% Include Table A.1: observation/future token counts, routing block index, spatial full-res groups F,
% and priority-tier segment counts K_p for mimic-video and DiT4DiT across all benchmarks.
\suppdraft{\Cref{tab:supp_schedules}} lists every reported cell.

On mimic-video, the 2,400 observation tokens are always kept and the budget counts future tokens: $F=100$ of the 300 groups per future frame stay at full resolution, which gives 600 tubes, and the three tiers hold 120, 180 and 300 tubes.
The segment counts of the tiers grow with the budget, and their weighted sum equals the future budget exactly.
Bridge keeps $F=200$ groups (900 tubes): with $F=100$ the operator cannot exceed 10,800 tokens,  its tier sizes keep the LIBERO proportions (20/30/50\%).
On DiT4DiT/LIBERO, the single future frame limits allocation to space, so budgets below 490 tokens must also coarsen the observed frame.
On RoboCasa-GR1, the two future frames allow one or two segments per tube; the 466-token cell combines spatial merging ($F=41$) with temporal merging of 74 tubes.

\paragraph{Optimization hyperparameters.}
 ARROW separates relevance learning from budget-specific decoder adaptation. In Stage 1, the router and a temporary decoder LoRA are jointly optimized using the task objective and router supervision. Spatial allocation uses 2 by 2 groups with F = 100, while the training-stage temporal operator employs uniform pooling. For LIBERO-Spatial and LIBERO-Goal, the temporal pooling configurations use 12, 10, or 8 segments; LIBERO-Object uses 8, 6, or 4 segments. The resulting compressed contexts provide task-gradient supervision for learning the router's relevance scores.

In Stage 2, the learned router is frozen, and the temporary decoder adapter is replaced by a freshly initialized, budget-specific LoRA. This adapter is trained using the actual deployment allocation schedule in \suppdraft{\cref{tab:supp_schedules}}, including relevance- and dynamics-aware temporal allocation. Thus, Stage 1 learns the routing scores, whereas Stage 2 adapts the action decoder to the final compressed context at each target budget. Both stages use the task objective in \suppdraft{\cref{eq:supp_task}}, with \suppdraft{$\lambda_{\mathrm{GT}}=0.02$}.

\paragraph{\suppdraft{DiT4DiT training recipe.}}
\suppdraft{Both LIBERO and RoboCasa-GR1 use the same two-stage organization: Stage~1 jointly training, and Stage~2 fresh adapter training for each deployment budget.
For each benchmark, the adopted Stage~1 router checkpoint is saved after 1,500 optimization steps; the budget-specific Stage~2 adapter is trained for 1,500 steps.
The Stage~1 peak learning rates are $10^{-4}$ for the router and $4\times10^{-5}$ for the adapter.
In Stage~2, the router remains frozen and the adapter peak learning rate is $4\times10^{-5}$.}

\emph{Latency.}
mimic-video is timed on an exclusively allocated H100 at batch size one with the Spatial checkpoints, including text encoding: three warm-up calls are followed by eight interleaved rounds of four calls per configuration, and we report the median of the 32 synchronized wall-clock times.
All configurations use CUDA graphs and folded adapters; on fixed inputs the folded and graphed policies match the eager trained adapters.
Text encoding takes about 150\,ms in every configuration (\suppdraft{\cref{fig:supp_latency_breakdown}}); at the 20\% budget the video DiT runs $1.87\times$ and the action decoder $1.98\times$ faster than in the full-context policy.
DiT4DiT is timed with the same protocol, including the VAE, cached text retrieval, current router scores and allocation, the video forward and all four action-flow steps; \suppdraft{\cref{tab:dit4dit_deployment}} lists the effect of each deployment optimization, all of which also apply to the full-context reference.
On the robot, an RTX 4090 shared with the control desktop runs the same protocol over 210 queries per method, including text encoding.

\emph{FLOPs.}
FLOPs are counted with PyTorch's FLOP counter on the same inputs.
TFLOPs cover the linear and convolution layers, consistently for all methods; mimic-video counts include the VAE and text encoder.

\suppdraft{\emph{Statistics.}
Each trained configuration uses one training seed.
The resulting checkpoint is evaluated with three evaluation seeds, keeping its trained weights fixed.
The training seed controls training randomness, whereas evaluation seeds control the stochastic policy execution during evaluation.
Variation across evaluation seeds therefore describes repeated evaluations of the same trained model.

For each evaluation seed, LIBERO uses 50 episodes per task across ten tasks, giving 500 episodes per suite and 1,500 episodes across the three seeds.
SIMPLER-Bridge uses 24 episodes per task across four tasks, giving 96 episodes per seed and 288 in total.
RoboCasa-GR1 uses 50 episodes per task across 24 tasks, giving 1,200 episodes per seed and 3,600 in total.
Methods are paired by benchmark, task, initial-state index, and evaluation seed; each comparison uses the corresponding episodes of its listed reference.

For evaluation seed $s$, the success rate is
$\mathrm{SR}_s=100\,N_s^{-1}\sum_{i=1}^{N_s}y_{s,i}$,
where $y_{s,i}\in\{0,1\}$ is the episode outcome.
The reported rate is the arithmetic mean
$\mathrm{SR}=\frac{1}{3}\sum_{s=1}^{3}\mathrm{SR}_s$.
With equal episode counts per seed, this also equals the success rate pooled over all three seeds.
We compute $\Delta=\mathrm{SR}_{\mathrm{variant}}-\mathrm{SR}_{\mathrm{reference}}$ in percentage points from the unrounded rates, equivalently averaging the paired episode-outcome differences over the three seeds.
Per-task count tables sum successful episodes across these seeds.
The separately specified held-out windows, coverage recordings, and real-robot trials retain their respective sample counts.}

\subsection{Baseline adaptation protocols}
\label{app:supp_baselines}

\ji{
    As external token-reduction baselines were originally designed for observation pruning in VLAs or multi-step diffusion WAMs, we adapt their selection rules to single-pass future-conditioned WAMs under matched Stage-2 LoRA training (\cref{tab:hyperparams}).
    On mimic-video, all baselines retain the 2,400 observation tokens, apply selection at video block 2, and preserve native source coordinates without feature rescaling.
    VLA-Pruner~\cite{liu2025vlapruner}, ADP~\cite{pei2026adp}, and CF-Prune~\cite{kim2026cfprune} score the 1,200 spatial positions of the final observed frame, retain 120 / 240 / 360 positions, and broadcast this spatial mask across all 14 future frames to yield 1,680 / 3,360 / 5,040 future tokens.
    Semantic text-relevance scores use mean raw scaled query-key logits across instruction tokens and heads (since video DiT cross-attention uses text keys only, making softmax sums over keys constant), while action attention averages across all action queries (excluding the proprioceptive query) and all 10 flow steps in FP32.
}


\paragraph{FastV-style.}
\ji{
    Following FastV~\cite{chen2024fastv}, future tokens are ranked by received visual self-attention at video block 2 (averaged across attention heads and visual queries), retaining the top tokens up to the target budget at their native coordinates.
}



\paragraph{VLA-Pruner.}

\ji{
    Following VLA-Pruner~\cite{liu2025vlapruner}, we take the union of the top-$k$ semantic positions and top-$k$ historical action-attention positions, then prune back to $k$ positions via greedy max-min cosine diversity on block-2 features.
    Historical action attention averages action-to-observation cross-attention over the deeper half of the decoder layers across the preceding 3 queries with exponential decay 0.8.
    To initialize this history without cross-episode leakage, the first 3 queries of every episode run at full context, raising measured mean token counts to 5,535 / 7,240 / 8,788 (marked with $^*$ in Tab.~1 of the main paper).
}



\paragraph{ADP.}
\ji{
    Following ADP~\cite{pei2026adp}, top-$k$ semantic token pruning is gated by end-effector displacement relative to the two preceding control steps: displacements below the prior two-step minimum trigger a full-context fallback, and at least one full-context query is forced after every three consecutive pruned queries.
    These fallbacks yield measured mean contexts of 12,101 / 13,059 / 13,881 tokens per query.
}


\paragraph{CF-Prune.}

\ji{
    CF-Prune~\cite{kim2026cfprune} extracts instruction and action attention from an initial denoising step to prune subsequent steps.
    Under single-step WAM inference, no prior denoising step exists; each query therefore runs an unadapted full-context probe pass (through video block 20 and the base decoder) to compute smoothed 50/50 complementary instruction-action scores (selecting low-entropy layers on the first episode query without multi-step phase gating), followed by the compressed LoRA-adapted pass.
    Charging both passes causes total FLOPs and latency to exceed single-pass Full-context inference (Tab.~1 of the main paper).
}


\paragraph{DiT4DiT.}
\ji{
    All four baselines follow the identical selection rules on DiT4DiT using observed/future token quotas of 392/197, 344/98, and 293/98 at the 589-, 442-, and 391-token budgets (thus pruning observation tokens as well at the two smaller budgets), each paired with a dedicated Stage-2 decoder LoRA.
}
